# ИИ-помощник по судьям (спринт 3)

Модуль расстановки судей по слотам и коллегиям (ТЗ п. 6.1.3, критерии готовности 10–13).
Схема, которую проверяем гипотезами H-03…H-05 спринта 2:

1. **Алгоритм** (жадный / OR-Tools CP-SAT) строит расстановку, которая гарантированно соблюдает правила.
2. **LLM-советник** объясняет решения, находит проблемные слоты, предлагает, кого пригласить, пишет текст приглашения.
3. Перед отправкой в LLM данные анонимизируются (ФИО → `judge_N`), таблица соответствия хранится у нас.
4. Окончательное решение всегда за организатором.

Входные данные уже есть: `registration/domain/availability.py` — кто в какие слоты может судить.
Жадная расстановка отображается в панели организатора (`/organizer/`).
Ссылка «Скачать проблемные слоты для H-07» выгружает JSON с оставшимися дефицитами.

После заполнения основных мест алгоритм назначает резерв из того же списка судей.
Для экспресса предусмотрен один резервный, для остальных форматов — до трёх.
Окно считается проблемным при нехватке основных или отсутствии резерва.
Если не хватает только резерва, JSON описывает одно незаполненное место
с причиной «Нет резервного судьи».

Если оценки заданы в настройке Django `USN_JUDGE_RATINGS` (словарь
«email из заявки → оценка»), алгоритм учитывает их при выборе судьи.
При отсутствии оценки выгружается `null`. В JSON судьи обозначаются кодами вида `J01`.
