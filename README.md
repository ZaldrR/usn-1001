# USN · сервис регистрации на соревнования и координации судей

Команда **«Тысяча и один промт»** (1001), проектный интенсив «Лаборатория ИИ-решений», Университет «Дубна».
Заказчик — Универсальная школа переговоров (USN).

> **Статус: скелет решения (спринт 2).** Работает на выдуманных тестовых данных из `mocks/`,
> без подключения к API заказчика. Полный функционал — в спринтах 3–5.

## Что это

Отдельный веб-сервис на **Python + Django** (страницы — HTML и CSS). Соревнования, роли и судейские слоты
организатор по-прежнему создаёт в Django Admin заказчика; наш сервис получает их **по API** и:

- даёт участникам форму регистрации в четырёх ролях (игрок, судья, секундант, зритель);
- показывает организатору заявки и карту доступности судей по слотам;
- в спринте 3 — ИИ-помощник для расстановки судей по слотам и коллегиям.

Сайт заказчика мы не меняем: связь только через его API.

## Что уже работает

| Часть | Где | Что делает |
|---|---|---|
| Список соревнований | `registration/views.py`, `templates/.../competition_list.html` | Соревнования и открытые роли |
| Форма регистрации | `registration/forms.py`, `templates/.../register.html` | Анкета, слоты судьи, игрок для секунданта, напарник для командного игрока, согласия; повторная отправка не создаёт дубль |
| Бизнес-правила | `registration/domain/rules.py` | Открытые роли, ошибка конфигурации, сочетание ролей, проверка формы |
| Карта доступности судей | `registration/domain/availability.py`, `templates/.../organizer.html` | Сколько судей в каждом слоте, проблемные слоты |
| Связь с API заказчика | `registration/usn_client.py` | Переключатель «моки / реальный API»; пути — заглушки до сверки со Swagger |
| Тесты | `registration/tests/` | 18 проверок: правила ролей, пограничные случаи, страницы |

## Запуск

Нужен Python 3.12 или новее.

```bash
python -m venv .venv
source .venv/Scripts/activate     # Windows (Git Bash); на macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate          # создать базу (один раз)
python manage.py load_demo        # загрузить тестовые заявки (по желанию)
python manage.py runserver        # сайт: http://127.0.0.1:8000
python manage.py test             # автотесты
```

## Структура

```
config/                 настройки Django-проекта
registration/           приложение регистрации
  domain/               правила и типы на чистом Python (без Django) — их же использует ИИ-модуль
  usn_client.py         связь с API заказчика (сейчас — моки)
  models.py             заявки и их статусы
  forms.py, views.py    форма и страницы
  templates/, static/   HTML и CSS
  tests/                автотесты
assignment/             место под ИИ-помощника по судьям (спринт 3)
mocks/                  выдуманные тестовые данные
docs/ARCHITECTURE.md    архитектура и решения
```

- Swagger заказчика смотрим вручную или только локальной нейросетью.
- Каждая задача — в своей ветке и через pull request.
