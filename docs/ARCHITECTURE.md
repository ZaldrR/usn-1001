# Архитектура (кратко)

Полная спецификация — лист «Спецификация архитектуры» в артефакте спринта 2 и документ
«Концепция MVP и пользовательские сценарии» v0.4.

```
Django Admin заказчика ──(создаёт соревнования, роли, слоты)──► API заказчика
                                                                  │ GET: соревнования, роли, слоты
                                                                  ▼
Участник ──► форма (forms.py) ──► domain/rules.py ──► БД заявок ──► POST: заявка в API заказчика
Организатор ──► панель (views.py) ──► domain/availability.py ──► assignment/ (ИИ, спринт 3)
```

## Решения

| № | Решение | Почему |
|---|---|---|
| Р-01 | Отдельный сервис на Python + Django, страницы на шаблонах (HTML + CSS) | Команда знает Python; заказчик на Django — проще встроить; ИИ-часть тоже на Python, один язык |
| Р-02 | Модульный монолит, а не микросервисы | До 50 соревнований в год, 3 разработчика, один деплой |
| Р-03 | Правила в `domain/` на чистом Python | Легко тестировать, переиспользуются ИИ-модулем |
| Р-04 | Слой `usn_client.py` с переключателем моков | Работаем без доступа к тестовой площадке; потом меняется только этот файл |
| Р-05 | ИИ-помощник = алгоритм + LLM-советник | Проверяется гипотезами H-03…H-05 |
| Р-06 | Анонимизация перед отправкой в LLM | Требование заказчика по персональным данным |

## Что не решено

- Какие данные, кроме заявок, принимает API заказчика (статусы, расстановка) — вопрос 6 «Концепции MVP».
- Реальные пути API — после сверки со Swagger.
- Способы входа (запрет иностранной авторизации с 07.07.2026) — вопрос 5 «Концепции MVP».
